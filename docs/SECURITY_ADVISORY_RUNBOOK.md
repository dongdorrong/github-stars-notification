# GitHub Security Advisory collector runbook

This collector is read-only, token-free in fixtures, and independent of the Release collector. New GHSA delivery is controlled by `intelligence.mode` and defaults to `shadow`; merging code does not enable production advisory Slack. Do not run commit-mode notification on a feature branch. No GitHub advisory create/edit/CVE/fork endpoint is called.

## API contract and permissions

The adapter pins `X-GitHub-Api-Version: 2022-11-28` and `Accept: application/vnd.github+json`. The [Global Advisory list](https://docs.github.com/en/rest/security-advisories/global-advisories?apiVersion=2022-11-28) is `GET /advisories`. Public listings require no fine-grained token permission and can be unauthenticated, though authenticated requests have a higher primary rate limit. The list supports `modified=<lower>..<upper>` (published **or** updated), `sort=updated`, `direction=asc`, cursor `after`/`before` from `Link`, and `per_page` up to 100. The default public list is reviewed/non-malware; malware/unreviewed require explicit `type` selection and are not enabled by this collector. An **independent bounded withdrawn scan** uses the documented `is_withdrawn=true` filter and a separate cursor so a withdrawal is not assumed to appear in the ordinary list.

Optional [Repository Advisory list](https://docs.github.com/en/rest/security-advisories/repository-advisories?apiVersion=2022-11-28) is `GET /repos/{owner}/{repo}/security-advisories?state=published&sort=updated&direction=desc`. Fine-grained access to protected resources requires **Repository security advisories: read**; classic PAT access to a private published advisory requires `repo` or `repository_advisories:read`. The endpoint documents cursor pagination but **not** a `modified`/`since` filter. The collector therefore scans bounded updated-desc pages with an overlapped local cutoff and never requests unpublished drafts. Repository source visibility must come from trusted inventory (`public`, `private`, `internal` or `unknown`); `published` alone does not prove a private repository advisory is public. If visibility is absent, it is `unknown` and excluded from public export/delivery.

The [REST pagination contract](https://docs.github.com/en/rest/using-the-rest-api/using-pagination-in-the-rest-api) supplies `Link rel="next"`; page length alone is not a completion signal. Continuation host/path and fixed query filters are validated before reuse. Each page is normalized completely before its proposed cursor may be persisted in the SQLite transaction. A failed page leaves the previous cursor intact. First scan is bounded by configured pages and a seven-day default window; its initial cohort is retained as `SUPPRESSED` without Slack. Successful completion advances a high-water mark, and subsequent scans overlap one hour by default for late edits. Nonterminal scans retain a Link continuation. Deep historical advisory completeness on every run is **not** claimed.

The [GitHub rate-limit guidance](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) notes 403/429 for primary or secondary limits. The reader distinguishes safe `rate_limited` when `Retry-After` or `X-RateLimit-Remaining: 0` is present, otherwise retains only `http_<status>`; it never logs response body, URL, headers or token. The request has an idle timeout plus a POSIX main-thread wall deadline under the caller budget. Unsupported alarm contexts fail closed as `budget_unavailable`. The public source can operate without a token at a lower rate limit; repository 403/404 is an optional-source capability degradation, not grounds to discard successful Global or Release pages. No source error silently advances its cursor.

## Identity, mapping and revisions

- Event ID and source ID: `github:ghsa:<uppercase GHSA-ID>`; one current raw event row regardless of Global/Repository duplicate observations.
- Deterministic project evidence precedence: official repository advisory URL, source code location, exact explicit package mapping, registry alias URL, reference URL; conflicting package/reference matches are ambiguous. A stronger official URL is not overridden by an unrelated weak reference.
- Unmapped/ambiguous Global Advisories remain raw state with an empty repository field and are suppressed from Slack. Do not assign ownership through AI.
- The allowlisted raw payload preserves GHSA/CVE IDs, advisory type/severity, CVSS v3/v4, EPSS, CWEs, affected package and vulnerable range/functions, first patched version, references, dates, withdrawal, public credits and source URLs. Private collaborators/fork internals returned by Repository Advisory API are dropped before persistence/feed.
- Every distinct normalized source content hash retains a revision. A separate material hash ignores EPSS, credits, whitespace-only description changes and updated timestamps, so these revisions alone do not requeue a delivered alert. Severity, CVSS, identifiers, affected/patched versions, description text and withdrawal are material. Withdrawn records remain auditable; the deterministic routing policy suppresses the withdrawn update rather than deleting history.
- Priority floor remains deterministic: critical → CRITICAL, high → HIGH, medium on a critical project → HIGH; AI may not demote it. Shadow rollout suppresses production GHSA Slack regardless of severity.

## Operations, recovery and rollback

Watch `advisory_pages`, `advisory_events`, `advisory_errors`, `signal_deferred`, `signal_budget_exhausted` and safe `signal_errors_by_type` in a **read-only preview**. Private source names must not be printed in public Actions output. A high error count or unsafe state validation is not a reason to reset the DB. Inspect permissions/rate budget privately, then retry the same source cursor. Repeated errors should be triaged without logging raw API responses. If a page is too large (8 MiB hard limit), lower `per_page` after preserving a backup and verifying cursor semantics; the default is 30.

SQLite v1→v2 migration and P0 rollback are documented in [Event schema reference](EVENT_SCHEMA_REFERENCE.md). A rollback to P0 code requires the verified pre-upgrade v1 DB backup; changing only `user_version` corrupts the contract and loses audit state. Before canary/full delivery, verify official GHSA mapping, withdrawal behavior, public visibility and bounded window metrics in shadow. Never test this adapter by sending a real Slack message.
